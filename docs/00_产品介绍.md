# 00 产品介绍

## 1. 若茗 PaaS 是什么

若茗 PaaS 是一套**面向开发者的企业级 AI 应用开发底座**。

它不是一个可以直接销售给最终用户的软件产品，而是帮助**开发团队**快速构建自己的企业应用或 SaaS 产品的基础框架。

**核心价值**：把每个企业应用都需要但又重复造的基础设施（权限、多租户、AI、日志、限流……）做好、做扎实，让开发者只需要专注在自己的业务逻辑上。

---

## 2. 解决什么问题

### 没有若茗，开发者面临的现实

一个典型的企业应用项目启动时，团队需要自己搭建：

```
权限系统（RBAC + 细粒度）         → 2-4 周
多租户数据隔离                    → 1-2 周
用户认证（JWT + Token 轮换）      → 1 周
操作审计日志                      → 1 周
接口限流 + 熔断                   → 1 周
接入大模型（LLM 网关）            → 1-2 周
AI Agent 编排                    → 2-4 周
知识库 RAG                        → 2-3 周
多环境配置管理                    → 3 天
结构化日志 + 链路追踪              → 3 天
─────────────────────────────────
合计：10-20 周，且质量参差不齐
```

**这些时间本应该花在业务功能上。**

### 有了若茗

```
上述所有基础设施  → 开箱即用，docker-compose up 即可
业务模块开发      → 按照规范新增模块，底层能力直接调用
上线时间          → 从 20 周缩短到 2-4 周（只需开发业务部分）
```

## 5. 适用场景

### ✅ 非常适合

**场景 1：企业内部系统快速交付**
> 公司需要一套 CRM / 项目管理 / 审批系统，需要权限、多租户、日志审计。
> 用若茗，专注做业务功能，底层直接复用。

**场景 2：AI SaaS 产品创业**
> 你想做一个面向企业的 AI 产品（如 AI 合同分析、AI 客服、AI 知识管理）。
> 若茗提供多租户 + AI Agent + RAG，你只需要做垂直业务逻辑。

**场景 3：独立开发者接外包项目**
> 企业客户要求有完整权限、日志、安全基线，若茗帮你直接满足这些要求。

**场景 4：中小团队 MVP 快速验证**
> 不想在基础设施上花时间，先跑通业务再说。

### ❌ 不适合

- 纯前端项目 / 静态网站
- 需要完全自定义技术栈（如必须用 Java / Go）
- 极简小工具，不需要权限和多租户

## 6. 核心设计理念

### 理念一：只写业务代码

底座负责：认证、权限、租户、日志、限流、AI 能力
你负责：业务模型、业务逻辑、业务接口、业务页面

### 理念二：模块可插拔

L0-L1 是不可禁用的核心，L2-L4 和 AI 模块按需启用。
你不需要某个模块，不启用它就不存在。

### 理念三：约定优于配置

遵守项目规范（目录结构、命名、基类继承），底层能力自动生效：
- 继承 `TenantAwareRepository`，多租户隔离自动工作
- 使用 `@audit_log` 装饰器，操作审计自动记录
- 继承 `BaseModel`，软删除、时间戳、租户字段自动有

### 理念四：AI 是一等公民

AI 能力不是"插件"，而是底座的原生组成部分。
每个租户可以独立配置 AI 模型、场景参数、知识库，无需修改代码。

### 理念五：生产可用，不是玩具

每一个设计决策都考虑生产环境的要求：
- Fail-Fast 配置校验（而不是运行时才报错）
- 双重跨租户防护（应用层 + 数据库层兜底）
- Token 重放攻击检测
- 非阻塞日志写入
- 向量检索 + 全文检索融合（而不是只有向量）
