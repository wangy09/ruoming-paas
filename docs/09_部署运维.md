# 09 部署运维

## 1. Docker Compose（开发/测试环境）

开发环境使用 `deploy/docker-compose.yml`，包含热重载功能：

### 服务列表

| 服务 | 说明 | 端口 |
|------|------|------|
| `postgres` | PostgreSQL 16 + pgvector | 5432 |
| `redis` | Redis 7（带持久化） | 6379 |
| `backend` | FastAPI 后端（开发热重载） | 8000 |
| `celery_worker` | 异步任务 Worker | - |
| `task_scheduler` | 计划任务调度器 | - |
| `frontend` | Vue3 + Vite 开发服务器 | 3000 |

### 一键启动

```bash
# 进入项目根目录
cd RuoMingPaas

# 复制开发环境变量
cp backend/.env.example backend/.env.development

# 一键启动
bash scripts/start.sh dev
```

启动成功后访问：

| 服务 | 地址 |
|------|------|
| 前端管理台 | http://localhost:3000 |
| 后端 API | http://localhost:8000 |
| API 文档 | http://localhost:8000/api/docs |
| 健康检查 | http://localhost:8000/api/health |

### 开发环境常用命令

```bash
# 查看服务状态
bash scripts/start.sh status

# 查看后端日志
bash scripts/start.sh logs backend

# 查看前端日志
bash scripts/start.sh logs frontend

# 停止服务
bash scripts/start.sh stop

# 手动执行数据库初始化（如需）
cd deploy
docker compose exec backend python /app/scripts/init_data.py
```

## 2. Docker Compose（生产环境）

生产环境使用 `deploy/docker-compose.prod.yml`，包含完整的服务编排和资源限制。

### 服务列表

| 服务 | 说明 |
|------|------|
| `frontend-builder` | 前端构建容器（产物写入共享 volume） |
| `nginx` | Nginx 反向代理（静态文件 + API 代理） |
| `postgres` | PostgreSQL 16 + pgvector（生产配置） |
| `redis` | Redis 7（带密码认证和内存限制） |
| `backend` | FastAPI 后端（生产模式） |
| `celery_worker` | 异步任务 Worker（生产模式） |
| `task_scheduler` | 计划任务调度器（生产模式） |

### 一键启动

```bash
# 进入项目根目录
cd RuoMingPaas

# 复制并配置生产环境变量
cp deploy/.env.production.example deploy/.env.production
vi deploy/.env.production

# 一键启动生产环境
bash scripts/start.sh prod
```

### 手动启动（不使用脚本）

```bash
cd /opt/RuoMingPaas/deploy

# 构建并启动
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build

# 查看容器状态
docker compose --env-file .env.production -f docker-compose.prod.yml ps

# 查看后端日志
docker compose --env-file .env.production -f docker-compose.prod.yml logs -f backend
```

## 4. Nginx 配置

生产环境 Nginx 配置位于 `deploy/nginx/nginx.prod.conf`：

```nginx
upstream ruoming_backend {
    least_conn;
    server backend:8000 max_fails=3 fail_timeout=30s;
    keepalive 32;
}

server {
    listen 80;
    server_name _;

    client_max_body_size 100M;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;

    # 前端静态资源
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
        }
    }

    # API 代理
    location /api/ {
        proxy_pass http://ruoming_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;
        proxy_read_timeout 120s;
    }

    # SSE 流式接口（AI 对话）
    location ~* /api/v1/ai/.*/stream {
        proxy_pass http://ruoming_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_read_timeout 300s;
        proxy_buffering off;
        add_header X-Accel-Buffering no;
    }
}
```

### SSL 配置（可选）

如需启用 HTTPS，在 Nginx 配置中添加：

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:DHE-RSA-AES256-GCM-SHA512:ECDHE-RSA-AES256-GCM-SHA384:DHE-RSA-AES256-GCM-SHA384;

    # ... 其余配置同上
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}
```

### 宿主机 Nginx 反向代理（可选）

> **适用场景**：当宿主机已安装 nginx 并占用 80/443 端口时，Docker nginx 改为只监听本地端口，由宿主机 nginx 反向代理。

**步骤 1：修改 Docker Compose 端口配置**

```yaml
# deploy/docker-compose.prod.yml
nginx:
  ports:
    - "127.0.0.1:8080:80"   # 只绑定本地，不暴露到公网
```

**步骤 2：配置宿主机 Nginx**

在宿主机 `/etc/nginx/conf.d/` 下新建配置文件：

```nginx
# /etc/nginx/conf.d/paas.conf
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
nginx -t && nginx -s reload
```

## 5. 数据库初始化

### 首次部署

```bash
cd /opt/RuoMingPaas/deploy

# 非破坏式建表
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python -c \
  "import asyncio; from app.database import init_db; asyncio.run(init_db())"

# 初始化基础数据
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python /app/scripts/init_data.py

# 初始化 Agent 种子数据
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python /app/scripts/seed_agents.py
```

成功输出示例：

```
✅ 若茗 PaaS 初始化完成！
   超管账号: admin
   超管密码: ruoming@2024
   API 文档: http://localhost:8000/api/docs
```

### 验证初始化数据

初始化完成后，可查询用户确认基础数据已写入：

```bash
cd /opt/RuoMingPaas/deploy
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm -T backend python - <<'PY'
import asyncio
from sqlalchemy import text

from app.database import AsyncSessionFactory


async def main():
    async with AsyncSessionFactory() as session:
        result = await session.execute(
            text("SELECT username FROM sys_user ORDER BY id LIMIT 5")
        )
        print([row[0] for row in result.fetchall()])


asyncio.run(main())
PY
```

如果输出中包含 `admin`，说明基础数据已初始化。

### 验证 Agent 数据

Agent 种子数据依赖 `init_data.py` 已执行完成。如需强制覆盖同名内置 Agent，使用 `--force` 参数：

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python /app/scripts/seed_agents.py --force
```

验证 Agent 是否已写入：

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm -T backend python - <<'PY'
import asyncio
from sqlalchemy import text

from app.database import AsyncSessionFactory


async def main():
    async with AsyncSessionFactory() as session:
        result = await session.execute(
            text("SELECT name FROM ai_agent WHERE is_deleted = false ORDER BY id")
        )
        print([row[0] for row in result.fetchall()])


asyncio.run(main())
PY
```

正常应看到 `闲聊助手`、`专业分析师`、`编程助理`、`知识库问答`、`创意写手` 等内置 Agent。

> 如果初始化时提示未找到可用模型配置，Agent 仍会创建，但 `model_config_id` 为空。后续需要登录前端，在「模型管理」中配置模型后，再到「Agent 管理」里绑定模型。

### 重置数据库（仅开发环境）

> **警告**：此操作会删除所有数据，仅在开发环境使用！

```bash
cd deploy
docker compose exec backend python /app/scripts/recreate_tables.py
docker compose exec backend python /app/scripts/init_data.py
docker compose exec backend python /app/scripts/seed_agents.py
```

## 9. 性能优化建议

### 资源配置

| 服务器规格 | 建议配置 |
|-----------|----------|
| 2核2G | 后端单实例，内存限制 768M |
| 4核4G | 后端单实例，内存限制 1536M |
| 8核8G+ | 后端多实例，可启用容器编排 |

### 前端构建优化

#### 问题：`npm run build` 卡死或服务器内存耗尽

**原因**：`vue-tsc` 类型检查遇到 TS 错误会卡住；Node.js 默认内存限制在低内存服务器上不够用。

**解决**：修改 `frontend/Dockerfile`，跳过 vue-tsc，限制内存：

```dockerfile
# 将原来的
RUN npm run build
# 改为
RUN NODE_OPTIONS="--max-old-space-size=1024" npx vite build
```

低配服务器上建议按服务顺序构建，避免后端和前端同时构建抢占内存：

```bash
cd /opt/RuoMingPaas/deploy
docker compose --env-file .env.production -f docker-compose.prod.yml build --no-cache backend
docker compose --env-file .env.production -f docker-compose.prod.yml build --no-cache frontend-builder
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
```

如果服务器只有 2G 内存且仍然 OOM，建议临时增加 swap 后再构建，或在本地/CI 构建镜像后推送到服务器运行。

#### 问题：`npx vite build` 报 `vite: Permission denied`

**原因**：前端构建上下文中包含宿主机的 `frontend/node_modules`，`COPY . .` 时覆盖了镜像内 `npm ci` 安装的依赖，导致 `node_modules/.bin/vite` 权限或平台依赖不正确。

**解决**：确保 `frontend/.dockerignore` 中排除以下目录和文件：

```text
node_modules
dist
.env
.env.*
```

服务器上如已经存在旧的构建缓存，可重新构建前端镜像：

```bash
cd /opt/RuoMingPaas/deploy
docker compose --env-file .env.production -f docker-compose.prod.yml build --no-cache frontend-builder
docker compose --env-file .env.production -f docker-compose.prod.yml up -d frontend-builder nginx
```

### Redis 优化

生产环境 Redis 已配置：
- `maxmemory 256mb`：内存上限
- `maxmemory-policy allkeys-lru`：LRU 淘汰策略
- `appendonly yes`：持久化

### PostgreSQL 优化

生产环境建议：
- 调整 `shared_buffers`（通常为内存的 1/4）
- 配置 `work_mem` 和 `maintenance_work_mem`
- 定期清理和重建索引

## 10. 常见问题

### 服务启动失败

```bash
# 查看容器状态
docker compose --env-file .env.production -f docker-compose.prod.yml ps

# 查看详细日志
docker compose --env-file .env.production -f docker-compose.prod.yml logs --tail=50 backend
```

### 数据库连接失败

```bash
# 检查数据库容器是否启动
docker exec ruoming_postgres pg_isready -U ruoming

# 检查数据库日志
docker compose --env-file .env.production -f docker-compose.prod.yml logs postgres
```

### 前端页面空白

```bash
# 检查后端健康
curl http://localhost:8000/api/health

# 检查前端构建是否成功
docker compose --env-file .env.production -f docker-compose.prod.yml logs frontend-builder
```

### 端口冲突

修改 `deploy/docker-compose.yml`（开发环境）或 `deploy/docker-compose.prod.yml`（生产环境）中的端口映射。

### PostgreSQL 密码认证失败

**现象**：`asyncpg: password authentication failed for user "ruoming"`

**原因**：Docker volume 中存有旧密码初始化的数据，修改密码后不生效。

**解决**：

```bash
# 停止服务
docker compose --env-file .env.production -f docker-compose.prod.yml down

# 删除旧 volume
docker volume rm deploy_postgres_data  # 或对应的 volume 名

# 重新启动
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
```

### Nginx 容器反复重启

**现象**：`docker compose ps` 显示 nginx 状态为 `Restarting`

**原因**：nginx 配置引用了不存在的 SSL 证书文件。

**解决**：改为纯 HTTP 配置，或先提供证书文件再启用 HTTPS。

### 环境变量未加载（POSTGRES_USER 为空）

**现象**：启动时报 `required variable POSTGRES_USER is not set`

**原因**：`.env.production` 文件没有被正确加载。

**解决**：确保 `docker-compose.prod.yml` 中所有需要环境变量的服务都配置了 `env_file`：

```yaml
env_file:
  - .env.production
```

### 初始化时报 `relation "sys_user" does not exist`

**现象**：`asyncpg.exceptions.UndefinedTableError: relation "sys_user" does not exist`

**原因**：数据库结构尚未创建，或使用了旧版本初始化流程。

**解决**：先执行非破坏式建表，再初始化种子数据：

```bash
cd /opt/RuoMingPaas/deploy

docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python -c \
  "import asyncio; from app.database import init_db; asyncio.run(init_db())"

docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python /app/scripts/init_data.py
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python /app/scripts/seed_agents.py
```

### `init_data.py` 事务中断

**现象**：`asyncpg.exceptions.InFailedSQLTransactionError`

**原因**：`_write_history` 方法写入 `sys_config_history` 表，但该表不存在，导致 asyncpg 事务进入 aborted 状态，后续所有 SQL 都失败。

**解决**：`sys_config_history` 已集成到 `app.database.init_db()` 的非破坏式建表流程中，重新执行建表即可：

```bash
cd /opt/RuoMingPaas/deploy
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend python -c \
  "import asyncio; from app.database import init_db; asyncio.run(init_db())"
```
