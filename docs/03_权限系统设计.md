# 03 权限系统设计

## 1. 设计目标

- **细粒度**：权限粒度到菜单、按钮、表格列
- **灵活性**：支持角色继承、权限叠加、数据范围控制
- **前后端一体**：后端校验 + 前端动态渲染，权限由后端驱动
- **可审计**：所有权限变更记录操作日志

> **安全声明**：前端权限控制（`v-permission` 指令、动态路由）仅用于改善 UX，隐藏无权限的 UI 元素。**真正的安全依靠后端接口层校验**，前端代码包含所有权限码是正常现象，不属于安全漏洞。

---

## 2. 权限模型（RBAC + 资源权限）

### 2.1 核心实体关系

```
User ──── UserRole ──── Role ──── RolePermission ──── Permission
 │                        │                               │
 │                        └── parent_id（角色继承）        │
 │                                                        │
 └── UserPermission（直接授权，绕过角色）                 │
                                                          │
Permission（统一管理所有权限类型，包含菜单树结构）：
  - type=menu：菜单页面访问（含 path/component/icon 等路由属性）
  - type=button：可点击某操作按钮（增删改导出等），权限码也用于后端接口校验
  - type=column：表格某列是否可见/可编辑

Role：
  - data_scope：数据权限范围（1全部/2本部门/3本部门及子/4本人/5自定义）
```

> **设计决策**：原设计中 `sys_permission` 与 `sys_menu` 存在字段冗余（`component`/`icon`/`is_visible` 两表均有），**本版本统一合并到 `sys_permission` 表**，以 `type=menu` 区分菜单类型权限。

### 2.2 权限类型说明

| 类型 | 用途 | 控制粒度 | 数据来源 |
|------|------|----------|----------|
| 菜单 | 页面级权限 | 谁能访问哪个页面 | 菜单管理页面 |
| 按钮 | 操作级权限 | 谁能执行什么操作 | 菜单管理页面 |
| 列 | 字段级权限 | 表格中能看到哪些列 | 菜单管理页面 |
| 数据 | 数据范围权限 | 能看到哪些数据 | 角色管理页面（data_scope） |

**说明**：
- **按钮类型**：权限码（如 `system:user:create`）既控制前端按钮显示，也控制后端 API 接口访问
- **数据类型**：通过角色的 `data_scope` 字段控制，不需要在菜单管理中单独配置

## 3. 角色继承机制

`sys_role` 表支持 `parent_id` 字段，子角色自动继承父角色的全部权限。

### 3.1 权限计算逻辑

```
用户最终权限 = 角色继承链权限 + 用户直接授权 - 用户黑名单
```

```python
# app/modules/permission/service.py

async def get_role_permission_codes(self, role_id: int) -> set[str]:
    """递归获取角色（含父角色）的全部权限码"""
    role = await self.db.get(SysRole, role_id)
    codes: set[str] = set()

    # 先取父角色的权限（递归，防止循环继承最多 10 层）
    if role.parent_id and role.parent_id != 0:
        parent_codes = await self.get_role_permission_codes(role.parent_id)
        codes.update(parent_codes)

    # 再取本角色权限（叠加）
    own_codes = await self._get_role_own_permission_codes(role_id)
    codes.update(own_codes)

    return codes

async def get_user_permission_codes(self, user_id: int) -> set[str]:
    """获取用户最终权限码集合"""
    # 1. 从所有角色（含继承）获取权限
    result = await self.db.execute(
        select(SysRole).join(SysUserRole, SysRole.id == SysUserRole.role_id)
        .where(SysUserRole.user_id == user_id)
    )
    codes: set[str] = set()
    for role in result.scalars().all():
        codes.update(await self.get_role_permission_codes(role.id))

    return codes
```

## 5. 后端权限校验

### 5.1 权限依赖注入

```python
# app/core/deps.py

def require_permissions(*codes: str):
    """
    按钮/API 权限依赖工厂
    用法：Depends(require_permissions("system:user:create"))
    """
    async def checker(
        current_user: SysUser = Depends(get_current_user),
        db: AsyncSession = Depends(get_db),
    ):
        # 超级管理员拥有所有权限
        if current_user.is_superplatform:
            return current_user

        # 获取用户权限码
        perm_service = PermissionService(db, redis)
        user_perms = await perm_service.get_user_permission_codes(current_user.id)

        # 校验是否有所需权限
        for code in codes:
            if code not in user_perms:
                raise HTTPException(
                    status_code=403,
                    detail=f"缺少权限: {code}"
                )
        return current_user
    return checker
```

### 5.2 路由使用示例


## 6. 前端权限实现

> **重要说明**：前端权限控制仅用于 UX（隐藏无权限的菜单和按钮），**不能作为安全手段**。所有敏感操作必须在后端接口层校验。

### 6.1 动态路由（完全由后端驱动）

前端不再硬编码业务路由，菜单和路由完全由后端 `/api/v1/my/permissions` 接口返回：

```typescript
// store/permission.ts
const modules = import.meta.glob('@/views/**/*.vue')

async function loadPermissions() {
  const res = await authApi.myPermissions()
  permissions.value = res.data

  // 动态注册路由
  const routes = convertMenuToRoutes(res.data.menus)
  routes.forEach(route => router.addRoute('root', route))
}

function convertMenuToRoutes(menus: MenuPermission[]): RouteRecordRaw[] {
  return menus
    .filter(menu => menu.isVisible)
    .map(menu => {
      const route: RouteRecordRaw = {
        path: menu.path,
        name: menu.path.replace(/\//g, '_'),
        meta: {
          title: menu.title,
          icon: menu.icon,
          permCode: menu.permissionCode,
        },
      }

      // 布局组件
      if (menu.component?.includes('BasicLayout')) {
        route.component = () => import('@/layouts/BasicLayout.vue')
        route.children = convertMenuToRoutes(menu.children || [])
      } else {
        // 普通页面组件
        const moduleKey = `/src/views/${menu.component}.vue`
        if (modules[moduleKey]) {
          route.component = modules[moduleKey]
        }
      }
      return route
    })
}
```

### 6.2 v-permission 自定义指令

```typescript
// src/directives/permission.ts
const permissionDirective = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding
    if (!value) return

    const permStore = usePermissionStore()
    const codes = Array.isArray(value) ? value : [value]
    const hasPermission = codes.some(code => permStore.hasPermission(code))

    if (!hasPermission) {
      el.parentNode?.removeChild(el)
    }
  },
}
```

## 7. 标签页（Tabs）功能

### 7.1 设计说明

- 标签页自动记录用户访问过的页面
- 首页固定为标签页，不可关闭
- 支持右键菜单：刷新、关闭、关闭其他、关闭全部
- 支持快捷操作下拉菜单

### 7.2 实现逻辑

```typescript
// store/app.ts
const visitedViews = ref<VisitedView[]>([])

function addVisitedView(view: VisitedView) {
  if (!view.path || visitedViews.value.some(v => v.path === view.path)) return
  visitedViews.value.push({ ...view, affix: view.meta?.affix })
}

function removeVisitedView(path: string) {
  visitedViews.value = visitedViews.value.filter(v => v.path !== path)
}
```

## 9. 权限缓存策略

```
用户登录 → 加载权限 → 存入 Redis（TTL: 30min）
权限变更（角色调整/权限分配）→ 清除相关用户 Redis 缓存
前端 → 登录时一次性获取权限数据 → 本地 Pinia 存储
```

## 10. 系统内置权限

### 10.1 设计说明

`is_system` 字段用于标识系统内置权限，保护核心权限不被误删：

- `is_system = true`：系统内置，删除按钮禁用
- `is_system = false`：用户创建的权限，可以删除

### 10.2 初始化数据

所有初始化数据（默认菜单、按钮权限、默认角色）均设置为 `is_system = true`：

- 租户管理员角色
- 普通用户角色
- 所有系统管理、审计日志、AI 管理的菜单和按钮权限
