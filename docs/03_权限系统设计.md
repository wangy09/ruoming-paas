# 03 权限系统设计

## 1. 设计目标

- **细粒度**：权限粒度到菜单、按钮、表格列、数据行
- **灵活性**：支持角色继承、权限叠加、权限排除
- **前后端一体**：后端校验 + 前端动态渲染，权限由后端驱动
- **可审计**：所有权限变更记录操作日志

> ⚠️ **安全声明**：前端权限控制（`v-permission` 指令、动态路由）仅用于改善 UX，隐藏无权限的 UI 元素。**真正的安全依靠后端接口层校验**，前端代码包含所有权限码是正常现象，不属于安全漏洞。

---

## 2. 权限模型（RBAC + 资源权限）

### 2.1 核心实体关系

```
User ──── UserRole ──── Role ──── RolePermission ──── Permission
 │                        │                               │
 │                        └── parent_id（角色继承）        │
 │                                                        │
 └── UserPermission（直接授权，绕过角色）                 │
                                                          │
Permission（统一管理所有权限类型，包含菜单树结构）：
  - type=menu：菜单页面访问（含 path/component/icon 等路由属性）
  - type=button：可点击某操作按钮（增删改导出等）
  - type=column：表格某列是否可见/可编辑
  - type=api：后端接口级权限（可选，与 button 联动）
  - type=data：数据范围权限（全部/本部门/本人/自定义）
```

> **设计决策（v2）**：原设计中 `sys_permission` 与 `sys_menu` 存在字段冗余（`component`/`icon`/`is_visible` 两表均有），**本版本统一合并到 `sys_permission` 表**，以 `type=menu` 区分菜单类型权限，`sys_menu` 表废弃。这与 django-vue-admin 的设计思路一致，维护更简洁。

## 3. 角色继承机制

`sys_role` 表新增 `parent_id` 字段，子角色自动继承父角色的全部权限，并可在此基础上叠加或排除特定权限。

```python
# app/modules/permission/service.py

async def get_role_permission_codes(self, role_id: int) -> set[str]:
    """
    递归获取角色（含父角色）的全部权限码
    """
    role = await self.role_repo.get_by_id(role_id)
    codes: set[str] = set()

    # 先取父角色的权限（递归）
    if role.parent_id:
        parent_codes = await self.get_role_permission_codes(role.parent_id)
        codes.update(parent_codes)

    # 再取本角色权限，叠加
    own_codes = await self.role_repo.get_permission_codes(role_id)
    codes.update(own_codes)

    return codes

async def get_user_permission_codes(self, user_id: int) -> set[str]:
    """
    获取用户最终权限码集合：
    角色权限（含继承） + 用户直接授权 - 用户黑名单排除
    """
    # 1. 从所有角色（含继承）获取权限
    roles = await self.user_repo.get_roles(user_id)
    codes: set[str] = set()
    for role in roles:
        role_codes = await self.get_role_permission_codes(role.id)
        codes.update(role_codes)

    # 2. 加上用户直接授权（白名单）
    direct_perms = await self.user_perm_repo.get_by_user(user_id, is_exclude=False)
    codes.update(p.code for p in direct_perms)

    # 3. 减去用户排除权限（黑名单）
    exclude_perms = await self.user_perm_repo.get_by_user(user_id, is_exclude=True)
    codes -= {p.code for p in exclude_perms}

    return codes
```

## 5. 后端权限校验

### 5.1 权限依赖注入

```python
# app/core/deps.py
from fastapi import Depends, HTTPException, status
from app.core.security import verify_token
from app.modules.permission.service import PermissionService

async def get_current_user(token: str = Depends(oauth2_scheme), db = Depends(get_db)):
    payload = verify_token(token)
    user = await UserService(db).get_by_id(payload["sub"])
    if not user or not user.status:
        raise HTTPException(status_code=401, detail="用户无效或已禁用")
    # 校验账号是否被锁定
    if user.locked_until and user.locked_until > datetime.utcnow():
        raise HTTPException(status_code=423, detail="账号已锁定，请稍后再试")
    return user

def require_permissions(*codes: str):
    """
    按钮/API 权限依赖工厂
    用法：Depends(require_permissions("system:user:create"))
    """
    async def checker(
        current_user = Depends(get_current_user),
        perm_service: PermissionService = Depends()
    ):
        if current_user.is_superuser:
            return current_user  # 超级管理员跳过
        user_perms = await perm_service.get_user_permission_codes(current_user.id)
        for code in codes:
            if code not in user_perms:
                raise HTTPException(
                    status_code=403,
                    detail=f"缺少权限: {code}"
                )
        return current_user
    return checker
```

### 5.3 列权限：响应过滤

```python
# app/modules/permission/checker.py
class ColumnPermissionFilter:
    """
    用于过滤响应数据中用户无权限的列
    """
    def __init__(self, resource_key: str):
        self.resource_key = resource_key

    async def filter_columns(self, data: list[dict], user_id: int, perm_service) -> list[dict]:
        allowed_columns = await perm_service.get_allowed_columns(user_id, self.resource_key)
        if not allowed_columns:
            return data  # 无列权限配置，返回全部
        return [
            {k: v for k, v in row.items() if k in allowed_columns}
            for row in data
        ]
```

### 5.4 数据权限：参数化条件注入（安全版）

> ⚠️ **已修复**：原设计通过字符串拼接返回 SQL 片段，存在 SQL 注入风险。本版本改为返回 **SQLAlchemy ORM 条件表达式**，全程参数化，不拼接原始 SQL 字符串。

```python
# app/modules/permission/data_scope.py
from enum import IntEnum
from sqlalchemy import and_, or_, Column
from sqlalchemy.orm import DeclarativeMeta

class DataScope(IntEnum):
    ALL = 1           # 全部数据
    DEPT_AND_SUB = 2  # 本部门及子部门
    DEPT = 3          # 本部门
    SELF = 4          # 仅本人
    CUSTOM = 5        # 自定义部门列表

async def get_data_scope_filter(user, role, model, db):
    """
    返回 SQLAlchemy 过滤条件（参数化，安全无注入风险）
    
    Args:
        model: 需要过滤的 ORM 模型类，需包含 creator_id / dept_id 字段
    Returns:
        SQLAlchemy BinaryExpression，可直接用于 .where()
    """
    scope = role.data_scope

    if scope == DataScope.ALL:
        return None  # 不加任何过滤

    elif scope == DataScope.SELF:
        # 使用参数化绑定，不拼接字符串
        return model.creator_id == user.id

    elif scope == DataScope.DEPT:
        return model.dept_id == user.dept_id

    elif scope == DataScope.DEPT_AND_SUB:
        sub_dept_ids = await get_sub_dept_ids(user.dept_id, db)
        # in_() 内部使用参数化绑定
        return model.dept_id.in_(sub_dept_ids)

    elif scope == DataScope.CUSTOM:
        custom_dept_ids = await get_role_custom_depts(role.id, db)
        return model.dept_id.in_(custom_dept_ids)

    return None


# 使用示例：
async def get_user_list(user, role, db):
    query = select(User)
    scope_filter = await get_data_scope_filter(user, role, User, db)
    if scope_filter is not None:
        query = query.where(scope_filter)
    result = await db.execute(query)
    return result.scalars().all()
```

## 6. 前端权限实现

> ⚠️ **重要说明**：前端权限控制仅用于 UX（隐藏无权限的菜单和按钮），**不能作为安全手段**。有技术能力的用户可通过 DevTools 绕过前端限制。所有敏感操作必须在后端接口层通过 `require_permissions` 进行二次校验。

### 6.1 登录后获取权限数据

```typescript
// store/permission.ts
import { defineStore } from 'pinia'
import { getMyPermissions, getMyMenus } from '@/api/permission'

export const usePermissionStore = defineStore('permission', {
  state: () => ({
    permissionCodes: [] as string[],       // 所有权限code集合
    buttonCodes: [] as string[],           // 按钮权限
    columnMap: {} as Record<string, string[]>,  // 列权限 resourceKey -> 可见列
    menus: [] as MenuItem[],               // 菜单树（从 sys_permission 中 type=menu 筛选）
    dynamicRoutes: [] as RouteRecordRaw[], // 动态路由
  }),
  actions: {
    async loadPermissions() {
      const [perms, menus] = await Promise.all([
        getMyPermissions(),
        getMyMenus(),
      ])
      this.permissionCodes = perms.codes
      this.buttonCodes = perms.buttons
      this.columnMap = perms.columns
      this.menus = menus
      this.dynamicRoutes = buildRoutes(menus)
    },
    hasPermission(code: string): boolean {
      return this.permissionCodes.includes(code)
    },
    hasButton(code: string): boolean {
      return this.buttonCodes.includes(code)
    },
    getVisibleColumns(resourceKey: string): string[] {
      return this.columnMap[resourceKey] ?? []
    }
  }
})
```

### 6.2 v-permission 自定义指令

```typescript
// components/Permission/directive.ts
import type { DirectiveBinding } from 'vue'
import { usePermissionStore } from '@/store/permission'

export const vPermission = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding  // 权限code 或 code数组
    const permStore = usePermissionStore()
    const codes = Array.isArray(value) ? value : [value]
    const hasAuth = codes.some(code => permStore.hasPermission(code))
    if (!hasAuth) {
      // 用注释节点占位，避免破坏 DOM 结构；v-if 场景下 Vue 也用注释节点
      el.parentNode?.replaceChild(document.createComment('v-permission'), el)
    }
  }
}

// 注册
// app.directive('permission', vPermission)
```

### 6.4 列权限：ProTable 集成

```typescript
// components/ProTable/index.vue
// ProTable 组件内部自动根据列权限过滤 columns

import { usePermissionStore } from '@/store/permission'

const props = defineProps<{
  resourceKey: string       // 对应后端资源标识
  columns: ColumnConfig[]   // 全量列配置
}>()

const permStore = usePermissionStore()

const visibleColumns = computed(() => {
  const allowedCols = permStore.getVisibleColumns(props.resourceKey)
  if (!allowedCols.length) return props.columns  // 无配置，显示全部
  return props.columns.filter(col => allowedCols.includes(col.prop))
})
```

### 6.5 动态路由生成

```typescript
// router/guard.ts
import { usePermissionStore } from '@/store/permission'
import router from './index'

router.beforeEach(async (to, from, next) => {
  const permStore = usePermissionStore()
  const token = getToken()

  if (!token) {
    if (to.path === '/login') return next()
    return next('/login')
  }

  if (!permStore.menus.length) {
    await permStore.loadPermissions()
    // 动态注册路由
    permStore.dynamicRoutes.forEach(route => router.addRoute(route))
    return next({ ...to, replace: true })  // 重新导航，确保路由生效
  }

  // 校验当前路由是否有权限访问（UX 层，后端接口仍会二次校验）
  const hasAccess = permStore.hasPermission(to.meta?.permissionCode as string)
  if (to.meta?.requireAuth && !hasAccess) {
    return next('/403')
  }
  next()
})
```

## 7. 权限管理接口设计


## 8. 权限缓存策略

```
用户登录 → 加载权限 → 存入 Redis（key: perm:{user_id}, TTL: 30min）
权限变更（角色调整/权限分配）→ 清除相关用户 Redis 缓存
                            → 通过 Redis Pub/Sub 通知其他 Worker 进程失效
前端 → 登录时一次性获取权限数据 → 本地 Pinia 存储
```

权限缓存数据结构（Redis Hash）：
