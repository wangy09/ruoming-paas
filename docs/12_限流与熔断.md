# 12 限流与熔断

> 企业级 PaaS 平台必须有多维限流保护，防止接口被爆破、AI 费用被耗尽、单租户拖垮整个系统。

---

## 1. 限流维度设计

| 维度 | 说明 | 典型配置 |
|------|------|---------|
| **全局 IP 限流** | 防 DDoS / 爆破 | 每 IP 每分钟 300 次 |
| **用户级限流** | 防单用户过度消耗 | 每用户每分钟 60 次 |
| **租户级限流** | 防单租户拖垮系统 | 每租户每分钟 500 次 |
| **接口级限流** | 高敏感接口细化控制 | 登录接口 10次/分钟 |
| **AI 推理限流** | 控制并发，配合 Token 配额 | 每用户每分钟 5 次 |

## 2. 技术选型：slowapi + Redis

`slowapi` 是 FastAPI 生态的限流库，基于 `limits` 库实现，支持 Redis 后端（分布式限流，多 Worker 共享计数器）。

## 3. 限流中间件配置

```python
# app/core/rate_limit.py
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address
from slowapi.errors import RateLimitExceeded
from fastapi import Request
from fastapi.responses import JSONResponse

def get_user_or_ip(request: Request) -> str:
    """限流 Key 生成：已登录用户用 user_id，未登录用 IP"""
    if hasattr(request.state, "user_id") and request.state.user_id:
        return f"user:{request.state.user_id}"
    return f"ip:{get_remote_address(request)}"

def get_tenant_key(request: Request) -> str:
    """租户级限流 Key"""
    tenant_id = getattr(request.state, "tenant_id", None)
    if tenant_id:
        return f"tenant:{tenant_id}"
    return f"ip:{get_remote_address(request)}"

# Redis 存储（分布式限流，多 Worker 共享）
limiter = Limiter(
    key_func=get_user_or_ip,
    storage_uri=settings.REDIS_URL,
    default_limits=["300/minute"],  # 全局默认限制
)


def custom_rate_limit_handler(request: Request, exc: RateLimitExceeded):
    """自定义限流响应格式"""
    return JSONResponse(
        status_code=429,
        content={
            "code": 429,
            "msg": f"请求过于频繁，请稍后再试。限制：{exc.detail}",
        },
        headers={"Retry-After": str(exc.retry_after)},
    )


# 注册到 FastAPI
def setup_rate_limit(app):
    app.state.limiter = limiter
    app.add_exception_handler(RateLimitExceeded, custom_rate_limit_handler)
```

## 5. 全局中间件限流（Nginx 层 + 应用层双重）

### 5.1 Nginx 层限流（第一道防线）

```nginx
# nginx.conf
http {
    # 按 IP 限流区域定义
    limit_req_zone $binary_remote_addr zone=api_ip:10m rate=100r/s;
    limit_req_zone $binary_remote_addr zone=login_ip:10m rate=5r/m;

    server {
        location /api/v1/ {
            limit_req zone=api_ip burst=200 nodelay;
            limit_req_status 429;
            proxy_pass http://fastapi_backend;
        }

        location /api/v1/auth/login {
            limit_req zone=login_ip burst=10 nodelay;
            limit_req_status 429;
            proxy_pass http://fastapi_backend;
        }
    }
}
```

### 5.2 应用层全局中间件（租户级限流）

```python
# app/core/middleware/tenant_rate_limit.py
from starlette.middleware.base import BaseHTTPMiddleware
import redis.asyncio as aioredis

class TenantRateLimitMiddleware(BaseHTTPMiddleware):
    """
    租户级 API 调用频率限制
    使用 Redis 滑动窗口计数器（每分钟）
    """

    async def dispatch(self, request: Request, call_next):
        tenant_id = getattr(request.state, "tenant_id", None)
        if not tenant_id:
            return await call_next(request)

        redis = request.app.state.redis
        window_key = f"rate:tenant:{tenant_id}:{int(time.time() // 60)}"

        count = await redis.incr(window_key)
        await redis.expire(window_key, 120)  # 2分钟 TTL

        # 从租户配置获取限流上限（可动态调整）
        tenant = await get_tenant_from_cache(tenant_id, redis)
        rate_limit = getattr(tenant, "max_api_per_minute", 500)

        if count > rate_limit:
            return JSONResponse(
                status_code=429,
                content={"code": 429, "msg": "租户 API 调用频率超限，请稍后再试"},
                headers={"Retry-After": "60"},
            )

        return await call_next(request)
```

## 6. 熔断器（Circuit Breaker）

适用于外部 AI 服务调用（追鹿大模型 API），防止外部服务故障时级联崩溃。

```python
# app/core/circuit_breaker.py
# 使用 pybreaker 库
# pip install pybreaker

import pybreaker

class CircuitBreakerConfig:
    FAIL_MAX = 5          # 连续失败 5 次触发熔断
    RESET_TIMEOUT = 60    # 60 秒后尝试半开

# AI 服务熔断器（每个 Provider 独立一个）
zhuilu_breaker = pybreaker.CircuitBreaker(
    fail_max=CircuitBreakerConfig.FAIL_MAX,
    reset_timeout=CircuitBreakerConfig.RESET_TIMEOUT,
    name="zhuilu_llm",
)

openai_breaker = pybreaker.CircuitBreaker(
    fail_max=CircuitBreakerConfig.FAIL_MAX,
    reset_timeout=CircuitBreakerConfig.RESET_TIMEOUT,
    name="openai_llm",
)


# 在 Provider 调用层使用
class ZhuiluProvider(BaseLLMProvider):

    @zhuilu_breaker
    async def chat(self, messages, model, **kwargs):
        """熔断器包裹：连续失败 5 次后自动熔断，60s 后恢复尝试"""
        resp = await self.client.post("/v1/chat/completions", json={...})
        resp.raise_for_status()
        return resp.json()["choices"][0]["message"]["content"]
```

熔断器状态监控接口：

```
GET /api/v1/admin/circuit-breakers    查看所有熔断器状态（超管）
POST /api/v1/admin/circuit-breakers/{name}/reset  手动重置熔断器
```

## 7. 限流响应与重试建议

所有限流响应统一格式，并在响应头携带重试时间：

```json
HTTP/1.1 429 Too Many Requests
Retry-After: 60
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1718600460

{
  "code": 429,
  "msg": "请求过于频繁，请 60 秒后再试",
  "data": null
}
```

前端 Axios 拦截器自动处理 429，弹出提示并禁止重复点击：

```typescript
// utils/request.ts
axiosInstance.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 429) {
      const retryAfter = error.response.headers['retry-after'] || 60
      ElMessage.error(`操作过于频繁，请 ${retryAfter} 秒后再试`)
      // 可选：记录限流事件，临时禁用对应按钮
    }
    return Promise.reject(error)
  }
)
```

## 8. 限流配置总结

| 接口/场景 | 限流策略 | 计数 Key |
|---------|---------|---------|
| 登录 | 10次/分钟 | IP |
| 注册 | 5次/分钟 | IP |
| 发验证码 | 3次/分钟 | IP |
| 普通 API | 60次/分钟 | 用户 ID |
| AI 对话 | 5次/分钟 | 用户 ID |
| AI Agent 执行 | 3次/分钟 | 用户 ID |
| 租户全局 | 500次/分钟 | 租户 ID |
| 全站默认 | 300次/分钟 | IP |
