# 12 限流与熔断

> 企业级 PaaS 平台必须有多维限流保护，防止接口被爆破、AI 费用被耗尽、单租户拖垮整个系统。

---

## 1. 限流维度设计

| 维度 | 说明 | 默认配置 |
|------|------|---------|
| **全局 IP 限流** | 防 DDoS / 爆破 | 每 IP 每分钟 300 次 |
| **用户级限流** | 防单用户过度消耗 | 每用户每分钟 60 次 |
| **租户级限流** | 防单租户拖垮系统 | 每租户每分钟 500 次 |
| **接口级限流** | 高敏感接口细化控制 | 登录接口 10次/分钟 |
| **AI 推理限流** | 控制并发，配合 Token 配额 | 每用户每分钟 30 次 |

## 2. 可配置限流服务

### 2.1 配置项清单

所有限流规则支持在配置中心动态修改，无需重启服务：

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `rate_limit.enabled` | bool | `true` | 是否启用限流（全局开关） |
| `rate_limit.global.default` | string | `100/minute` | 全局默认限流 |
| `rate_limit.ip.default` | string | `300/minute` | IP 级默认限流 |
| `rate_limit.user.default` | string | `60/minute` | 用户级默认限流 |
| `rate_limit.tenant.default` | string | `500/minute` | 租户级默认限流 |
| `rate_limit.api.login` | string | `10/minute` | 登录接口限流 |
| `rate_limit.api.register` | string | `5/minute` | 注册接口限流 |
| `rate_limit.api.captcha` | string | `3/minute` | 验证码接口限流 |
| `rate_limit.ai.chat` | string | `30/minute` | AI 对话限流 |
| `rate_limit.ai.agent` | string | `30/minute` | AI Agent 执行限流 |

### 2.2 配置格式

限流值格式为 `数字/单位`，支持以下单位：

| 单位 | 说明 | 示例 |
|------|------|------|
| `second` | 每秒 | `10/second` |
| `minute` | 每分钟 | `60/minute` |
| `hour` | 每小时 | `1000/hour` |
| `day` | 每天 | `10000/day` |

### 2.3 配置缓存机制

配置中心 → Redis 缓存（60秒 TTL）→ 内存缓存（进程内）

修改配置后，最长 60 秒内自动生效，也可手动调用接口刷新缓存：

```
POST /api/v1/config-center/invalidate
```

## 3. 技术实现

### 3.1 slowapi + limits + Redis（接口级限流）

使用 `slowapi` 库实现接口级限流，支持 Redis 分布式存储：

```python
# app/core/rate_limit.py
from slowapi import Limiter
from slowapi.util import get_remote_address
from app.config import settings

def get_ip_key(request: Request) -> str:
    """按 IP 限流 Key"""
    return f"ip:{get_remote_address(request)}"

def get_user_key(request: Request) -> str:
    """按用户限流 Key（已登录用 user_id，未登录用 IP）"""
    user_id = getattr(request.state, "user_id", None)
    if user_id:
        return f"user:{user_id}"
    return get_ip_key(request)

limiter = Limiter(
    key_func=get_user_key,
    storage_uri=settings.REDIS_URL,
    default_limits=[settings.RATE_LIMIT_DEFAULT],
)
```

### 3.2 租户级限流中间件

基于 Redis 滑动窗口计数器实现全局租户级限流：

```python
# app/core/middleware/rate_limit.py
class TenantRateLimitMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        if not await is_rate_limit_enabled():
            return await call_next(request)

        tenant_id = getattr(request.state, "tenant_id", None)
        if tenant_id:
            limit = await get_rate_limit("tenant.default")
            # Redis 滑动窗口计数...

        return await call_next(request)
```

### 3.3 限流配置服务

从配置中心动态读取限流规则：

```python
# app/core/rate_limit_config.py
class RateLimitConfig:
    async def is_enabled(self) -> bool:
        """检查限流是否启用"""
        val = await self.get("rate_limit.enabled")
        return val.lower() == "true"

    async def get_limit(self, rule_name: str) -> str:
        """获取指定规则的限流值"""
        return await self.get(f"rate_limit.{rule_name}")
```

## 5. 限流响应格式

所有限流响应统一格式，并在响应头携带限流信息：

```json
HTTP/1.1 429 Too Many Requests
Retry-After: 60
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 0

{
  "code": 429,
  "message": "请求过于频繁，请稍后再试。限制：10/minute",
  "data": null
}
```

### 前端处理

```typescript
// frontend/src/utils/request.ts
axiosInstance.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 429) {
      const retryAfter = error.response.headers['retry-after'] || 60
      ElMessage.error(`操作过于频繁，请 ${retryAfter} 秒后再试`)
    }
    return Promise.reject(error)
  }
)
```

## 6. 熔断器（Circuit Breaker）

### 6.1 功能概述

适用于外部服务调用（AI 模型、第三方集成），防止外部服务故障时级联崩溃。

**状态流转**：
- **CLOSED**：正常，所有请求正常通过
- **OPEN**：熔断中，直接返回错误或切换备用
- **HALF_OPEN**：半开状态，允许少量请求尝试恢复

### 6.2 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `fail_threshold` | 5 | 连续失败次数阈值 |
| `open_timeout` | 60s | 熔断持续时间 |
| `fail_ttl` | 120s | 失败计数过期时间 |

### 6.3 支持的熔断类型

| 类型 | 说明 |
|------|------|
| `llm` | AI 模型调用 |
| `integration` | 第三方集成（飞书、钉钉、企微） |
| `websearch` | 网页搜索 |
| `codegen` | 代码生成 |

### 6.4 使用方式

```python
# 在 AI Provider 中使用
from app.core.circuit_breaker import CircuitBreaker, CircuitState

class ZhuiluProvider(BaseLLMProvider):
    async def chat(self, messages, model, **kwargs):
        breaker = CircuitBreaker("llm", model_config_id)
        
        state = await breaker.get_state()
        if state == CircuitState.OPEN:
            # 熔断处理：切换备用模型或返回错误
            raise AppException(SysErrCode.SERVICE_UNAVAILABLE)
        
        try:
            result = await self.client.post(...)
            await breaker.on_success()
            return result
        except Exception:
            await breaker.on_failure()
            raise
```

## 8. Nginx 层限流（可选）

作为应用层限流的补充，在 Nginx 层设置第一道防线：

```nginx
http {
    limit_req_zone $binary_remote_addr zone=api_ip:10m rate=100r/s;
    limit_req_zone $binary_remote_addr zone=login_ip:10m rate=5r/m;

    server {
        location /api/v1/ {
            limit_req zone=api_ip burst=200 nodelay;
            limit_req_status 429;
            proxy_pass http://fastapi_backend;
        }

        location /api/v1/auth/login {
            limit_req zone=login_ip burst=10 nodelay;
            limit_req_status 429;
            proxy_pass http://fastapi_backend;
        }
    }
}
```
