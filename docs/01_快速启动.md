# 01 快速启动

> 目标：15 分钟内在本地启动若茗 PaaS，进入前端管理台并打开 API 文档。

## 环境要求

| 工具             | 版本要求  | 检查命令                     |
| -------------- | ----- | ------------------------ |
| Docker         | 24.0+ | `docker --version`       |
| Docker Compose | 2.20+ | `docker compose version` |
| Git            | 任意    | `git --version`          |

## 步骤一：进入项目目录

```bash
cd RuoMingPaas
```

如果是新机器，请先克隆项目并进入仓库根目录。

## 步骤二：准备环境变量

开发环境只需要后端环境文件：

```bash
cp backend/.env.example backend/.env.development
```

`scripts/start.sh` 在未发现 `backend/.env.development` 时也会自动复制模板，并提示你检查后重新运行。开发阶段至少确认 `SECRET_KEY`、模型密钥、文件上传等配置是否符合当前环境。

## 步骤三：一键启动

```bash
bash scripts/start.sh dev
```

脚本会完成以下工作：

- 检查 Docker 和 Docker Compose。
- 启动 `deploy/docker-compose.yml` 中的 PostgreSQL、Redis、Backend、Celery Worker、任务调度器和 Frontend。
- 等待后端健康检查通过。
- 检查平台超管是否存在，首次启动时执行 `backend/scripts/init_data.py` 初始化种子数据。
- 检查 Agent 是否存在，首次启动时执行 `backend/scripts/seed_agents.py` 初始化 Agent 数据。
- 输出前端、API 文档、健康检查和默认账号。

常用脚本命令：

```bash
bash scripts/start.sh status
bash scripts/start.sh logs
bash scripts/start.sh logs backend
bash scripts/start.sh logs frontend
bash scripts/start.sh stop
```

## 本地开发模式

如果不使用 Docker 运行后端和前端，需要自行准备 PostgreSQL 16（带 pgvector）和 Redis 7。

### 后端

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install uv
uv pip install -e ".[dev]"

cp .env.example .env.development
APP_ENV=development alembic upgrade head
python scripts/init_data.py
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认代理到 `localhost:8000`，访问 `http://localhost:3000`。

## 服务说明

开发环境 Compose 服务：

| 服务               | 说明                    |
| ---------------- | --------------------- |
| `postgres`       | PostgreSQL + pgvector |
| `redis`          | 缓存、权限缓存、任务队列          |
| `backend`        | FastAPI 后端，开发热重载      |
| `celery_worker`  | 知识库等异步任务 Worker       |
| `task_scheduler` | 计划任务调度器               |
| `frontend`       | Vite 开发服务器            |

前端容器使用独立 `frontend_node_modules` volume，避免宿主机目录反复删除或重装依赖导致 `node_modules` 损坏。

## 常见问题

### 启动后前端空白

先确认后端健康检查通过：

```bash
curl http://localhost:8000/api/health
bash scripts/start.sh logs backend
```

### 看不到新增菜单

重新执行初始化脚本补齐内置菜单并清理权限缓存：

```bash
cd deploy
docker compose exec backend python /app/scripts/init_data.py
```

然后重新登录。

### AI 或 Agent 不可用

先在平台 `AI 管理 / 模型管理` 中配置模型并验证可用，再创建或绑定 Agent。

### 计划任务没有立即执行

启用计划任务时，如果下一次执行时间为空，调度器只会初始化下一次执行时间，不会立刻执行。可在 `系统监控 / 计划任务` 中手动点击“立即执行”。

### 端口冲突

修改 `deploy/docker-compose.yml` 中 `3000`、`8000`、`5432`、`6379` 的端口映射，或停止占用端口的服务。

## 附录：环境变量说明

以下是 `.env.development` 中的关键变量（其他变量有注释说明）：

```bash
# 应用环境（development / test / production）
APP_ENV=development

# 数据库连接（使用 Docker 时保持默认即可）
DATABASE_URL=postgresql+asyncpg://ruoming:ruoming@localhost:5432/ruoming_dev

# Redis 连接
REDIS_URL=redis://localhost:6379/0

# JWT 密钥（开发环境随意填，生产环境必须是强随机值）
SECRET_KEY=dev-secret-key-change-in-production

# 默认 AI 提供商（zhuilu / openai / ollama）
AI_DEFAULT_PROVIDER=openai
OPENAI_API_KEY=sk-your-api-key-here

# 追鹿大模型（有账号则填写）
# ZHUILU_API_KEY=your-zhuilu-key
# ZHUILU_BASE_URL=https://api.zhuilu.xxx
```
