# 若茗 PaaS 生产环境部署指南

> 本文档根据实际部署过程整理，记录了完整的部署步骤及常见问题的解决方案。
> 服务器环境：阿里云 ECS（2核2G），CentOS/Alibaba Cloud Linux，已有宿主机 nginx。

---

## 一、前置条件

- 服务器已安装 Docker 和 Docker Compose
- 服务器已有宿主机 nginx（占用 80/443 端口）
- 域名已解析到服务器公网 IP（本例：`paas.aibobo.top`）
- 项目代码已上传到服务器（本例路径：`/opt/RuoMingPaas`）

---

## 二、配置文件准备

### 2.1 创建 `.env.production`

在 `/opt/RuoMingPaas/deploy/` 目录下创建 `.env.production`：

```env
# 数据库
POSTGRES_USER=ruoming
POSTGRES_PASSWORD=your_password
POSTGRES_DB=ruoming_prod
DATABASE_URL=postgresql+asyncpg://ruoming:your_password@ruoming_postgres:5432/ruoming_prod

# Redis
REDIS_PASSWORD=your_redis_password
REDIS_URL=redis://:your_redis_password@ruoming_redis:6379/0

# 应用
SECRET_KEY=your_secret_key
APP_ENV=production
```

> **注意**：密码中如包含 `!`、`$`、`#` 等特殊字符，在 shell 中使用时需加引号，但写入 `.env` 文件本身不需要转义。

### 2.2 Docker Compose 端口配置

由于宿主机 nginx 已占用 80/443 端口，Docker nginx 改为只监听本地 8080：

```yaml
# deploy/docker-compose.prod.yml
nginx:
  ports:
    - "127.0.0.1:8080:80"   # 只绑定本地，不暴露到公网
```

同时 postgres/redis 服务需显式加载 env_file：

```yaml
postgres:
  env_file:
    - .env.production

redis:
  env_file:
    - .env.production
```

### 2.3 Docker nginx 配置（纯 HTTP）

暂无 SSL 证书时，使用纯 HTTP 配置（`deploy/nginx/nginx.prod.conf`）：

```nginx
upstream ruoming_backend {
    least_conn;
    server backend:8000 max_fails=3 fail_timeout=30s;
    keepalive 32;
}

server {
    listen 80;
    server_name _;

    client_max_body_size 100M;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;

    location / {
        root   /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
        }
    }

    location /api/ {
        proxy_pass http://ruoming_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;
        proxy_read_timeout 120s;
    }

    # SSE 流式接口（AI 对话）
    location ~* /api/v1/ai/.*/stream {
        proxy_pass http://ruoming_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_read_timeout 300s;
        proxy_buffering off;
        add_header X-Accel-Buffering no;
    }
}
```

### 2.4 宿主机 nginx 反代配置

在宿主机 `/etc/nginx/conf.d/` 下新建配置文件：

```nginx
# /etc/nginx/conf.d/paas.conf
server {
    listen 80;
    server_name paas.aibobo.top;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
nginx -t && nginx -s reload
```

## 三、前端构建优化

### 问题：`npm run build` 卡死或服务器内存耗尽

**原因**：`vue-tsc` 类型检查遇到 TS 错误会卡住；Node.js 默认内存限制在低内存服务器上不够用。

**修改 `frontend/Dockerfile`**，跳过 vue-tsc，限制内存：

```dockerfile
# 将原来的
RUN npm run build
# 改为
RUN NODE_OPTIONS="--max-old-space-size=512" npx vite build
```

**修改 `frontend/vite.config.ts`**，移除 `manualChunks` 减少内存峰值：

```typescript
// 删除或注释掉 rollupOptions.output.manualChunks 配置
```

## 五、数据库初始化

### 5.1 建表

项目没有 alembic 迁移文件，使用脚本建表：

```bash
# 将最新脚本同步到容器（如本地有修改）
docker cp /opt/RuoMingPaas/backend/scripts/recreate_tables.py deploy-backend-1:/app/scripts/recreate_tables.py

# 执行建表（会删除并重建所有表，生产环境谨慎执行）
docker exec deploy-backend-1 python /app/scripts/recreate_tables.py
```

> **重要**：`recreate_tables.py` 会 `drop_all` 再 `create_all`，执行后所有数据清空。仅首次部署或需要重置时使用。

### 5.2 初始化种子数据

```bash
docker exec deploy-backend-1 python /app/scripts/init_data.py
```

成功输出示例：

```
✅ 若茗 PaaS 初始化完成！
   超管账号: admin
   超管密码: ruoming@2024
   API 文档: http://localhost:8000/api/docs
```

## 六、常见问题与解决方案

### 问题 1：postgres 密码认证失败

**现象**：`asyncpg: password authentication failed for user "ruoming"`

**原因**：Docker volume 中存有旧密码初始化的数据，修改密码后不生效。

**解决**：
```bash
# 停止服务
docker compose -f docker-compose.prod.yml down

# 删除旧 volume
docker volume rm deploy_postgres_data  # 或对应的 volume 名

# 重新启动
docker compose -f docker-compose.prod.yml up -d
```

### 问题 2：nginx 容器反复重启

**现象**：`docker compose ps` 显示 nginx 状态为 `Restarting`

**原因**：nginx 配置引用了不存在的 SSL 证书文件。

**解决**：改为纯 HTTP 配置（见 2.3 节），或先提供证书文件再启用 HTTPS。

### 问题 3：环境变量未加载（POSTGRES_USER 为空）

**现象**：启动时报 `required variable POSTGRES_USER is not set`

**原因**：`.env.production` 文件只被 `backend` 等服务加载，`postgres`/`redis` 没有配置 `env_file`。

**解决**：在 `docker-compose.prod.yml` 中为 postgres/redis 添加：
```yaml
env_file:
  - .env.production
```

### 问题 4：`init_data.py` 事务中断

**现象**：`asyncpg.exceptions.InFailedSQLTransactionError`

**原因**：`_write_history` 方法写入 `sys_config_history` 表，但该表不存在，导致 asyncpg 事务进入 aborted 状态，后续所有 SQL 都失败。

**解决**：`sys_config_history` 没有 ORM 模型，需用原生 SQL 手动建表（已集成到 `recreate_tables.py`）：
```bash
docker exec ruoming_postgres psql -U ruoming -d ruoming_prod -c "
CREATE TABLE IF NOT EXISTS sys_config_history (
    id          BIGSERIAL PRIMARY KEY,
    config_key  VARCHAR(256) NOT NULL,
    scope_type  VARCHAR(20) NOT NULL,
    scope_id    BIGINT,
    old_value   TEXT,
    new_value   TEXT,
    changed_by  BIGINT,
    changed_at  TIMESTAMPTZ DEFAULT NOW(),
    remark      TEXT
);"
```

### 问题 5：后端报 `relation "xxx" does not exist`

**现象**：访问页面报 500，日志显示某张表不存在。

**原因**：`recreate_tables.py` 缺少部分模块的导入，导致对应表未被创建。

**解决**：确认 `recreate_tables.py` 包含以下导入，然后重新执行建表：
```python
from app.modules.integration.models import SysIntegrationConnection, SysExternalIdentity, SysContactSyncLog
```

如不想清空数据，可直接补建缺失的表：
```bash
docker exec ruoming_postgres psql -U ruoming -d ruoming_prod -c "
CREATE TABLE IF NOT EXISTS sys_integration_connection (
    id BIGSERIAL PRIMARY KEY,
    provider VARCHAR(64) NOT NULL,
    name VARCHAR(128) NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT true,
    is_default BOOLEAN NOT NULL DEFAULT false,
    capabilities JSONB,
    config JSONB,
    encrypted_config TEXT,
    status SMALLINT NOT NULL DEFAULT 1,
    last_test_status VARCHAR(32),
    last_test_message TEXT,
    sort INTEGER NOT NULL DEFAULT 0,
    created_by BIGINT,
    updated_by BIGINT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    is_deleted BOOLEAN NOT NULL DEFAULT false,
    tenant_id BIGINT
);
CREATE TABLE IF NOT EXISTS sys_external_identity (
    id BIGSERIAL PRIMARY KEY,
    local_id BIGINT NOT NULL,
    provider VARCHAR(64) NOT NULL,
    external_id VARCHAR(256) NOT NULL,
    connection_id BIGINT,
    identity_type VARCHAR(32) NOT NULL DEFAULT 'user',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    is_deleted BOOLEAN NOT NULL DEFAULT false
);"
```

## 七、日常运维命令

```bash
# 查看所有容器状态
docker compose -f /opt/RuoMingPaas/deploy/docker-compose.prod.yml ps

# 查看后端日志（实时）
docker logs deploy-backend-1 -f --tail 100

# 重启某个服务
docker compose -f /opt/RuoMingPaas/deploy/docker-compose.prod.yml restart backend

# 更新后端镜像并重启（不影响其他服务）
docker compose -f /opt/RuoMingPaas/deploy/docker-compose.prod.yml build backend
docker compose -f /opt/RuoMingPaas/deploy/docker-compose.prod.yml up -d backend

# 将本地文件同步到容器（无需重建镜像）
docker cp ./scripts/some_script.py deploy-backend-1:/app/scripts/

# 进入后端容器
docker exec -it deploy-backend-1 bash

# 进入数据库
docker exec -it ruoming_postgres psql -U ruoming -d ruoming_prod
```
